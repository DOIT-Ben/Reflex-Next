# Reflex Next 后端生产化长期执行目标

现在给你一个目标：将 Reflex Next 后端持续推进到可以正式上线、公开推广、稳定安装、长期运行和持续维护的 `v1.0.0` 生产级状态。

在这个目标完成之前，不允许因为完成一份报告、一个阶段、一个小修复或一次提交而停止。必须持续观察、判断、执行、验证、复盘并选择下一步，直到全部完成标准有可复现证据，或触发明确停止条件。

## 1. 先理解真实目标

- 用户要的是可正式推广的完整桌面产品后端，不是只有测试通过的开发原型；
- 当前项目采用 Python Core + Python Runtime/插件 + Tauri 2/Rust Host；
- 旧 PyQt 项目只作为行为基线，不得迁回旧 UI 架构；
- 当前 Core、Runtime、插件和 Rust Host 已有较强离线测试，匿名 Cloud 额度、反馈和质量发布闭环已实现，主要缺口是生产安全、真实 Provider、长期运行、可观测性、Cloud 多实例、升级回滚和发布制度；
- 前端由独立人员重做，后端必须提供稳定、版本化、可测试的契约，并及时向前端交付兼容说明。

开始每轮工作前读取：

1. `AGENTS.md`
2. `docs/ARCHITECTURE.md`
3. `docs/MIGRATION.md`
4. `docs/BACKEND-PRODUCTION-ROADMAP.md`
5. `workbench/backend-production-tasks.md`
6. 与当前任务直接相关的源码、测试和验证记录

## 2. 长期执行地图

- 终极愿景：个人用户能够安全、稳定地使用本地桌面 AI 文本工具，并能理解 Provider、隐私、历史和本地模型边界；
- 当前阶段：`v0.7.0-alpha.8` 生产化收尾。阶段 0/1 已关闭，阶段 2 仅剩当前提交的构建物/SBOM 复核，Cloud Beta 和 PostgreSQL 多实例并发证据已完成，阶段 3 仅剩正式 72 小时浸泡；
- 近期目标：完成 72 小时浸泡、当前提交的构建物/SBOM 证据、Windows 10 生命周期和真实旧版本升级验证；
- 中期方向：安全与本地数据、性能与长期运行、脱敏可观测性；
- 发布方向：安装、升级、回滚、代码签名、受控试用和 `v1.0.0`；
- 长期维护：Provider 兼容、依赖安全、季度浸泡、协议与数据兼容审查；
- 非目标：云端账号、云同步、强制遥测、默认重模型、公开插件市场、Core 重写；可选 Cloud 服务不改变本地 Core 边界。

## 3. 持续执行循环

1. 观察：读取任务账本、当前代码、测试、Git 状态和上一轮证据；
2. 判断：从当前阶段选择价值最高且依赖已满足的任务；
3. 拆解：将任务拆成互不冲突的安全、可靠性、性能、测试发布工作包；
4. 并发：把独立工作包交给多个子智能体，同时明确文件所有权、禁止事项和验收命令；
5. 集成：主智能体审查每个结果，拒绝越界修改、重复实现和未经证实的结论；
6. 验证：先跑目标测试，再以低资源并发跑统一后端门禁；涉及桌面、安装或真实 Provider 时补实机证据；
7. 复盘：更新任务状态、验证结果、风险和版本门禁；
8. 交付：按项目格式提交并推送已通过验证的阶段变更；阶段门禁通过后再创建标签；
9. 继续：阶段完成后立即进入下一阶段最高价值任务，不把“建议下一步”当作停止理由。

## 4. 执行约束

- 保持外科式改动，不做无关重构、换栈、批量格式化或清理；
- 不修改或暂存未跟踪 `resources/`；
- Core 不得依赖 PyQt、Tauri API、SQLite 默认初始化、pyperclip、torch、sentence-transformers 或 huggingface-hub；
- Provider、历史、翻译、批处理、Markdown、语义模型和桌面能力继续保持插件/宿主边界；
- 不读取、打印、记录、提交或硬编码真实 API Key、token、账号或凭据；
- 不使用聊天中曾出现的密钥；真实冒烟必须使用新生成并由用户通过设置页保存的凭据；
- 不执行 `git reset --hard`、强制 checkout、递归删除、数据库清空、密钥轮换或不可逆发布操作；
- 不自动引入强制云端遥测、上传诊断或改变隐私默认值；可选质量分析和改进计划必须默认关闭并逐项授权；
- 子智能体不得使用或修改 `.superpowers` 和 `docs/superpowers`；
- 已通过的行为契约必须用测试保护，不能用文档声明替代实现证据。

## 5. 验证标准

- Python：按包隔离执行 Core、Runtime 和全部插件测试；
- Rust：限制为最多 2 个测试线程；
- TypeScript：运行 Domain Bridge 测试和生产构建；
- 安全：依赖审计、权限矩阵、敏感信息扫描、恶意输入夹具；
- 可靠性：真实 Provider 冒烟、取消、超时、重试、Sidecar 崩溃恢复；
- 性能：冷启动、首状态、取消时延、10,000 次 Mock 浸泡、1,000 次混合调用；
- 数据：历史损坏、备份恢复、密钥轮换中断、导出取消；
- Cloud 数据：授权删除、质量发布来源、PostgreSQL 多实例发布/回滚和备份恢复；
- 发布：干净 Windows 构建、安装、覆盖安装、卸载、重装、回滚和包审计。

每次宣称通过时必须记录实际命令、退出码、测试数量、产物路径或实机证据。不能把静态检查当作完整运行证据。

## 6. 完成标准

- `docs/BACKEND-PRODUCTION-ROADMAP.md` 的全部 `v1.0` 门禁通过；
- `workbench/backend-production-tasks.md` 中 `P0` 到 `P5` 无未完成发布阻塞项；
- Cloud Beta 的 PostgreSQL 多实例门禁和公开部署门禁有独立证据；
- 自动测试、真实 Provider、长期浸泡、数据恢复和安装生命周期均有证据；
- P0/P1 安全与可靠性问题为 0；
- 版本、安装包、标签、校验和、SBOM 和发布说明一致；
- 正式包可验证来源、可安装、可升级、可卸载、可回滚；
- 前端可以只依赖稳定公开契约完成集成；
- 用户和支持人员能通过脱敏错误与诊断处理常见问题；
- `v1.0.0` 已提交、推送、打标签并完成发布包审计。

如果某个阶段完成，立即进入下一阶段；只有整体完成标准全部满足才可结束长期目标。

## 7. 停止条件

- 需要用户提供或操作新凭据、代码签名证书、付费服务或外部账号；
- 需要不可逆删除历史、配置、模型或发布物；
- 需要改变隐私、遥测、商业或 Provider 策略；
- 项目规则与目标冲突；
- 连续两轮验证失败且必须由用户选择互斥取舍；
- 当前操作会影响第三方权益或执行未经授权的外部写入；
- 整个长期目标已经达到全部完成标准，且不存在可安全推进的高价值事项。

除这些情况外，持续执行，不重复请求已经获得的常规实施授权。
