# Reflex 签名、更新与回滚规范

状态：签名流程已冻结，实际证书和正式发布仍待采购与授权。
适用目标：Windows x64 安装包、Host 和 Runtime 三个可执行物。

## 1. 签名对象

每次候选发布必须对以下三个文件分别执行 Authenticode 签名：

- `Reflex_<版本>_x64-setup.exe`
- `Reflex.exe`
- `reflex-runtime.exe`

签名前先完成构建、敏感信息扫描和 SHA-256 计算；签名后必须重新计算哈希并写入候选目录的 `SHA256SUMS.txt`。

## 2. 证书要求

- 使用组织批准的代码签名证书，证书用途必须包含 Code Signing；
- 私钥只存在于受控签名环境或硬件密钥服务，不进入 Git、构建目录、环境变量、日志或安装包；
- 签名账户启用最小权限和双人复核；
- 证书到期、吊销或时间戳异常时，停止发布，不用另一张未经批准的证书替代；
- 时间戳服务必须使用组织批准的 HTTPS 地址，并使用 SHA-256 时间戳摘要。

## 3. 推荐操作顺序

1. 在干净发布工作树构建三个可执行物。
2. 运行统一后端验证、前端构建、依赖审计和构建物敏感扫描。
3. 用签名环境执行等价于以下命令的签名操作：

```powershell
signtool sign /fd SHA256 /td SHA256 /tr <已批准的时间戳服务> /a .\artifacts\Reflex_<版本>_x64-setup.exe
signtool sign /fd SHA256 /td SHA256 /tr <已批准的时间戳服务> /a .\artifacts\Reflex.exe
signtool sign /fd SHA256 /td SHA256 /tr <已批准的时间戳服务> /a .\artifacts\reflex-runtime.exe
```

4. 使用 `Get-AuthenticodeSignature` 和 `signtool verify /pa /all` 检查三个文件的签名链、时间戳和用途。
5. 重新生成 12 个组件 SBOM 和 6 份用户文档的候选物料。
6. 用发布候选验证器执行 `-RequireSigned -RequireTag -RequireClean`；任何一个门禁失败都不能发布。
7. 在独立机器上验证安装、启动、生成、取消、历史读取和卸载，再公开校验和及来源说明。

## 4. 更新策略

当前版本不提供自动更新。正式加入更新机制前，更新包必须同时具备：

- HTTPS 下载和完整性校验；
- 签名验证失败时拒绝安装；
- 版本降级默认拒绝，用户明确执行回滚时才允许；
- 更新前自动保留配置、历史和上一版本安装包；
- 更新失败后能恢复到上一版本并保留原始数据目录。

更新服务不得把 Provider 密钥、历史正文或反馈内容上传到更新服务器。

## 5. 回滚规则

只有签名有效、来源匹配、校验和一致的上一版本安装包可以回滚。执行步骤以
[RELEASE-RECOVERY.md](RELEASE-RECOVERY.md) 为准：先退出应用、备份当前数据、卸载当前版本，再安装并验证上一版本。

旧版本写入新版本迁移过的历史库前，必须有跨版本兼容证据；没有证据时保留当前数据库和迁移备份，不强行覆盖。

## 6. 发布失败处理

- 证书、时间戳、校验和、来源标签或工作树任一不一致：废弃候选目录并重新构建，不在原目录修补；
- 安装或启动失败：保留安装日志、版本和诊断编号，不收集密钥或完整正文；
- 回滚失败：停止写入数据目录，保留全部备份，转入人工恢复流程；
- 任何疑似私钥泄露：立即吊销证书并暂停所有发布，不尝试覆盖历史记录。
